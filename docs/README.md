# Mount Storage — Documentation

`mount-storage` **attaches VHD / VHDX virtual disks automatically when
Windows starts, before any user profile is loaded.** It runs as a Windows
service that the User Profile Service depends on, so the disks are already
mounted when Windows loads the user profiles — the profiles (or any other
data) can live on them.

The main use is a **software RAID1 (mirror) on a laptop or PC with two
drives**, without BIOS RAID and without booting from Storage Spaces:

```
C:\Storage\Storage-X-1.vhdx   (on the NVMe drive, BitLocker)  ─┐
                                                               ├─ Storage Spaces mirror ─> E:  (user data, profiles)
D:\Storage\Storage-X-2.vhdx   (on the SATA drive, BitLocker)  ─┘
```

Windows can mount a VHDX by hand (Disk Management, `Mount-VHD`), but it
does not mount it again after a restart. Storage Spaces needs both disks
present at boot. `mount-storage` does exactly that: it reads a list of
disk files and attaches each one, every time Windows starts.

```
Windows boot
  └─ Service Control Manager
       ├─ "Mount Storage" service  <-- this tool: attach the disks listed in mount-storage.cfg
       └─ User Profile Service     (depends on "Mount Storage", starts after it)
            └─ user logon, profile loaded from the mounted storage
```

## Why it exists

| Problem | What `mount-storage` does |
|---------|---------------------------|
| A VHDX mounted by hand is gone after a restart | attaches every disk listed in `mount-storage.cfg` at each start-up |
| The disks must be there before the user profile is loaded | installs a service and makes the User Profile Service depend on it; the service reports "running" only after the disks are attached |
| Windows 11 "fast startup" resumes the kernel instead of booting, services do not start again | installs a scheduled task that runs on resume (`--task`) |
| The volume holding a disk file may not be ready yet at boot (BitLocker unlock) | checks every file is readable, retries 3 times, one second apart |
| Something went wrong | writes `mount-storage.log` next to the executable |

## Concepts at a glance

| Need | Command (administrator console) |
|------|---------------------------------|
| Install the service and the start-up task | `mount-storage --install` |
| Remove everything installed | `mount-storage --uninstall` |
| Mount the listed disks now, from the console | `mount-storage --run` |
| Start / stop the installed service | `mount-storage --start` / `--stop` |
| Show usage / license / version | `mount-storage --help` / `--license` / `--version` |

The executable **always runs as administrator** (its manifest requires
it; Windows shows the UAC prompt when started from a normal console).

## Platform

`mount-storage` is **Windows only** (Windows 10 / 11, x64): it uses the
Virtual Disk API (`virtdisk`), the Service Control Manager and the Task
Scheduler.
